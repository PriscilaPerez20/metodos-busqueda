6.3. Búsqueda por Funciones Hash

¿Qué es una búsqueda Hash?

La búsqueda por funciones Hash (o dispersión) es un método de acceso directo a los datos basado en una clave. A diferencia de la búsqueda secuencial o la binaria, aquí no se realizan comparaciones sucesivas elemento por elemento. En su lugar, se utiliza una función matemática (función hash) que transforma una clave de entrada (como un nombre, un número de control o un ID) directamente en un índice numérico dentro de una tabla, indicando la posición exacta donde se encuentra o debe almacenarse el elemento.

Cómo funciona (paso a paso)
  1. Se recibe el dato o clave de búsqueda que se desea localizar (por ejemplo, una matrícula escolar).
  2. La clave se introduce en la función hash (como la operación módulo, por ejemplo: `clave % tamaño_tabla`).
  3. La función realiza el cálculo matemático y arroja un valor numérico entero que corresponde al índice de la tabla.
  4. El sistema accede directamente a esa posición de memoria en tiempo récord para recuperar o verificar el registro.
El problema de las Colisiones

Una colisión ocurre cuando la función hash procesa dos claves diferentes y arroja exactamente el mismo resultado numérico (el mismo índice). Como dos datos no pueden ocupar el mismo espacio en la tabla al mismo tiempo, los algoritmos hash implementan métodos de resolución de colisiones, tales como:

  • Encadenamiento (Chaining): Cada posición de la tabla apunta a una lista enlazada; si hay colisión, el nuevo elemento se agrega a la lista de esa misma posición.
  • Prueba Lineal (Linear Probing): Si la casilla está ocupada, el sistema busca de forma secuencial en la siguiente casilla disponible.
Ventajas y Desventajas
  • Velocidad insuperable: Es el método más rápido para recuperar información en el mejor de los casos, logrando un acceso prácticamente inmediato.
  • Ideal para bases de datos: Es la técnica fundamental detrás de diccionarios, tablas asociativas e indexación de grandes volúmenes de registros.
  • Consumo de memoria (Desventaja): Requiere reservar espacio de memoria adicional para la tabla hash, y su eficiencia disminuye si ocurren demasiadas colisiones.
Complejidad algorítmica
  • Mejor caso y Caso promedio: O(1) — acceso directo e instantáneo a través de la clave.
  • Peor caso: O(n) — ocurre cuando hay un exceso de colisiones y el sistema se ve obligado a buscar de manera lineal dentro de la estructura afectada.
  • Espacio: O(n) — depende directamente del tamaño de la tabla hash y el almacenamiento de las claves.
